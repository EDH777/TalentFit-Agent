# 人员准备与系统准备使用说明

适用页面：项目组队 → 人员准备 / 系统准备。2026-10-27更新。默认页面只帮助人事准备员工、工作日和每日可投入比例。

## 先理解三个概念

- **当前岗位**回答“主要从事哪类工作”。知识库岗位分类与员工当前岗位使用同一来源，八类固定选项，也可留待确认。
- **能力依据**回答“有效简历明确证明了什么”。岗位分类不能替代技能；能力尚未派生不影响岗位显示。
- **人员排期**回答“哪天还能安排多少时间”。公司工作日、每日可投入比例和已有安排共同决定能否参加新项目。

## 百分比怎么算

100%表示一个标准工作日，50%表示半个工作日。按公司实际工作日标准理解，不固定为8小时。

**剩余可安排 = 每日可投入比例 − 已安排比例。**

例如某日可投入80%，已有项目安排30%，剩余50%。仍应填写可投入80%，系统扣减已有安排；不要再手动填成50%。

公司日历默认周一至周五工作、周末休息；工作日没有个人覆盖时，系统默认可投入100%。人事只需在请假、调休或临时限制时调整个人日期。显式设为未知后才会进入“未知”状态。填写总比例不会自动分配项目，生成和提交方案也不占排期，管理员明确批准后才新增安排。

该百分比表达与 Microsoft Project 的最大可用比例/任务投入比例、Asana 的 Percent allocation 一致。原实现并非某个产品的直接复刻，本次将技术化的“容量、单位”换成业务表达。

参考：[Microsoft Project](https://support.microsoft.com/en-us/project/learn-more-about-resource-units)、[Asana](https://help.asana.com/s/article/capacity-planning?language=en_US)。

## 建议顺序

1. 人事在知识库上传简历；模型选择八类岗位之一，无依据则待确认。
2. 在“人员准备”点击“从知识库建立档案”，核对同名身份。岗位立即读取主简历分类，无须等待能力抽取。
3. 在人员准备查看默认公司日历；只有节假日/调休等特殊日期需要修改，再按员工/日期填写请假或特殊限制比例。
4. 如有上线前已有项目，进入“系统准备”登记真实已有安排，管理员核对后关闭初始化。
5. 到项目列表新建组队项目，只填写项目目标、日期和岗位，保存即确认需求，点击“生成推荐”。
6. 查看推荐依据，人事提交审批，管理员批准后才正式占用排期。

发布包不预置员工和项目排期。建议先用 README 中的流程建立员工档案，再练习生成、冲突和未知场景。

## 员工档案与岗位

| 字段或操作 | 含义与使用 |
|---|---|
| 从知识库建立档案 | 将已入库简历连接到员工身份，每批最多100份；不同于每批最多3份的文件上传 |
| 默认关联选择 | 没有同名员工时建立新身份；重名时等待明确选择，不自动合并 |
| 明确新建独立员工 | 确实是另一位同名人员时使用 |
| 选择已有员工 | 将资料关联给已存在身份，请核对工号或UUID |
| 员工编号 / UUID | 工号可由人事维护；未填显示UUID前8位，悬停可看完整标识 |
| 部门 | 人事维护的业务字段，不影响技能证据 |
| 当前岗位 | 从有效主简历的岗位分类立即读取，来源显示知识库同步；不再依赖“能力资料是否派生” |
| 维护档案 | 修改姓名、工号、部门、当前岗位与在职状态。岗位固定八类，可清空为待确认；保存后同步知识库 |
| 在职状态 | 在职才进入正常组队范围；有当前或未来已有安排时不能通过停用/离职绕过安排 |
| 刷新 | 重新读取当前状态，不自动调用模型或生成排期 |

八类岗位为产品经理、前端开发工程师、后端开发工程师、测试工程师、AI应用开发工程师、现场实施工程师、硬件工程师、采购经理。

原目标职位字段已移除。旧资料只将明确对应的岗位和少量已确认别名合并；无法确认的仍待确认。员工页和知识库可互相修改岗位，旧表单遇到版本变化须刷新，避免覆盖另一入口的新值。

第一份关联成为主简历。增加第二份资料不会自动切换主简历，同名不会自动合并，删除/解除资料不抹掉员工历史安排。

## 员工详情

员工档案列表支持按姓名、工号、部门和当前岗位搜索；默认只展示备选人员。人事可以将没有当前/未来占用的员工移出备选，员工、简历和历史排期会保留；在“已移出”筛选中可以恢复。项目列表默认隐藏已归档项目，使用状态筛选中的“已归档”可以再次查看历史项目。

### 简历能力依据

查看技能、岗位事实、项目经历及可核对的子段短引用。内容只读。

“尚未派生”表示还未提取能力事实；打开或刷新员工页不会触发提取，项目生成时会按当前有效主简历派生。模型遗漏常见技术词时，系统会基于当前有效子段做逐字引用校验补全；项目经历明确写入的技术栈也会用于技能匹配。部分演示人员已用真实模型准备有效引用缓存。

“可用”表示当前事实可读取；“已过期”通常来自主简历/分段/抽取版本变化；“资料不可用”需检查主关联和分段开关。未记载不等于不会，否定、他人技能和冲突项不能作为必备技能依据。

### 可投入时间日历

1. 填开始日期和结束日期（都包含当天），点击“刷新日历”。最多查询90个自然日。
2. 月历每天直接显示工作日/休息日、可投入比例、已安排比例和剩余比例；点击某天查看占用项目。
3. 人事可以在当天占用明细中调整未来日期、结束占用或取消占用；调整只能影响今天及未来，历史日期保留。
4. 可投入比例的批量维护仍遵循0～100整数规则；“未知”必须由人事明确保存，默认工作日没有覆盖时为100%。

已有安排不能通过降低可投入比例或改为未知来清除；保存值不得小于已生效安排。没有个人覆盖的工作日按100%显示。读取演示来源时显示警告；人事明确修改后会变为人工维护来源。

占用明细中的“结束”会保留历史记录并释放该占用的当前及未来日期；“取消”同样保留审计记录但不再计入可安排比例；“调整”会保留旧记录并新建调整后的占用。项目详情和项目列表的人事操作还提供“提前结束项目”和“取消项目”，会在一个事务中释放该项目全部有效占用；释放后可以归档项目。

如果员工在已经排期的日期请假，先在员工日历中把当天可投入比例设为 0%。系统发现当天已有占用时会返回冲突并列出项目，随后在人事日历的当天明细中调整、结束或取消占用，再保存请假比例。这样不会把请假日静默计算成超配。

### 简历关联与主版本

完整简历关联和主简历切换属于高级维护，不是默认组队流程；需要时回到知识库或高级维护入口。

“员工关联简历”为完整关联清单：添加为新增关联，移除为解除关联，保存后生效，不删除原资料。“明确选择主简历”只能选当前已关联资料中的一份。

主关联切换会改变岗位来源并令旧能力事实失效；不会合并历史技能。资料ID与创建时间由系统带入，不需要手填。

## 公司工作日

公司哪天工作与某人当天能投入多少是两件事，必须分别维护。

| 操作 | 用法 |
|---|---|
| 开始日期/结束日期（含） | 确定读取范围，最多366天；例如11月2日至4日包含2日、3日、4日 |
| 读取公司日历 | 默认生成周一至周五工作、周末休息；同时显示手动覆盖的特殊日期 |
| 日期勾选框 | 只用于调整节假日、调休等特殊日期，普通工作日无需逐日保存 |
| 新增明确日期 | 按YYYY-MM-DD逐项填写，用逗号或换行分隔，保存时作为明确工作日 |
| 保存明确工作日 | 保存读取列表的勾选状态和新增日期，未提交不生效 |

## 系统准备：初始化已有占用

用于补录系统上线前已存在的项目和人员安排，不是创建新的待审批组队方案。

1. 在“系统准备”点击“登记已有项目”：填写项目名称、实际依据、开始和结束日期（都包含当天）。
2. 选已有项目、员工和区间，点击“读取可用公司工作日”，多选实际安排日期。
3. 填“每日已安排比例（%）”1～100整数及安排依据，点击“登记基础占用”。成功即写入已有安排，不再等待方案审批。

日期须位于已有项目区间，最多90天；只有明确工作日和已知可投入比例才可安排，合计不能超出当天可投入比例。正式项目的占用通过员工日历明细结束、取消或调整；历史记录不会删除。

管理员在“系统准备”点击“核对并关闭初始化”后还需二次确认永久关闭。关闭不可重开；之后仍可维护员工、工作日和每日可投入比例，但新增项目安排必须走方案审批。没有原有项目时不必虚构记录，也仍需核对并关闭初始化才能正式批准新方案。

## 权限与常见情况

人事维护资料、工作日、排期、需求并提交方案；管理员只读员工台账，可关闭初始化及批准/驳回方案。后端校验实际角色。

| 情况 | 下一步 |
|---|---|
| 知识库有资料但员工表为空 | 从知识库建立档案，两步分开 |
| 当前岗位待确认 | 在知识库或员工档案选择合适类别，不等能力派生 |
| 提示主简历/岗位已变化 | 刷新并重新编辑，不覆盖另一入口新值 |
| 有可投入比例却缺工作日 | 公司工作日还未明确维护 |
| 生成时等待补充时间 | 查询提示日期；没有个人覆盖的正常工作日默认100%，只有明确标记未知才需要补充 |
| 名额缺必备技能依据 | 补充真实履历分段或调整要求，不能只改岗位类别 |
| 已有安排拒绝保存 | 核对日期、工作日、员工状态、已知比例及剩余比例 |
| 初始化已关闭 | 不能再直接登记已有安排，使用正式方案审批 |
